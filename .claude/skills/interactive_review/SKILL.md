We are doing an interactive QA process. $ARGUMENTS

1. Review our current branch and give a rundown of what changed and how it affects the product.
2. Gather information and make a Product Oriented summary of the features affected and how they work now.
    a. Use text-based diagrams (CLI-friendly):
        * Indented trees or tables for relationships
        * Numbered sequences with → arrows for flows
        * Bulleted lists for grouping domains & ideas
3. Wait for the user instructions
4. Apply user instructions
5. Re-evaluate the product requirements and specifications then extend/improve our documentation
6. Ensure all required test cases exist
7. Review everything and do a final check-in with the user
