We are doing a generic audit to our platform focusing on documentation.

Our goal is to ensure that documenation stays accurate while being comprehensive, helpfull and complete.

1. Start the audit by listing the folder/file structure of the project (focusing on the backend in /lib) to get a high level idea of what we are building.
2. Read the top level domain modules to understand everything on a high level
3. Make a deeper dive into the specifics of each feature
4. Update the documentation inside the modules

Note that the documentation will be published as Hexdoc. 

In addition to the module and function docs we want to create guides that help the user understand everything on a high level. 

Finally we want to ensure README.md and CLAUDE.md are also helpfull and kept up to date.

What makes a good documentation:

 - Hierarchical (starts from high level concepts only to delve into specifics later on)
 - Diagrams (represent complex relations or flows with text or mermaid diagrams)
 - Helpfull and consise (the goal is to help the reader get the most insight on how things work, but **not overburden** them with information)
 - Examples (for function and module docs provide with examples the user can relate to)
 - Complete (does not leave out important information)
 - Write like a Perfectionst (the details matter, use HexDocs standards in writing great documentation)
